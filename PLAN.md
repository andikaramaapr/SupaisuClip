## (c) Frontend EditState Requirements

The frontend `EditState` **must be a 1-to-1 mirror of `RenderParams`**. Key implementation notes:

- `video_filename` — set from upload/download response
- `clip_start` / `clip_end` — drive timeline scrubber bounds
- `webcam_src` / `webcam_dst` — set via canvas drag handles; must pass as `Rect` objects (not flat values)
- `webcam_style` — object `{ border_px, border_color, radius_px }`
- `highlight_words` — array of strings; frontend word-picker populates it
- `srt_relative` — when frontend generates a "trimmed" SRT starting at 0, set this `true`; otherwise leave `false`
- `style_key` — must be one of the keys in `SUBTITLE_STYLES` from `/api/assets` response
- `encoder` — default `"auto"`; let user override from `/api/system/encoders` list
- `resolution` — only `1080` or `720` accepted (not `540`; that is internal preview-only)
- `preview_seconds` — set to e.g. `10` for quick preview render; `null` for full export
- For ASS preview, send `PreviewAssRequest = { ...editState, absolute_time: false }` to `/api/preview/ass`

## (d) Bugs Found in Existing Code

> Do NOT fix — list only.

### BUG-1: `/api/render` (legacy) missing many RenderParams fields
`POST /api/render` is a `multipart/form-data` endpoint (legacy sync). It hardcodes only a subset of `RenderParams` form fields and **does not expose**:
- `srt_relative`, `clip_start`, `clip_end`
- `main_y_offset`, `main_zoom`
- `webcam_style` (partial — has `webcam_src_json`/`webcam_dst_json` but no style)
- `hook_font_size`, `hook_color`, `hook_box_color`, `hook_mode`
- `primary_color` has hardcoded default `#FFFF00` (instead of `None`)
- `font_size` has hardcoded default `64` (instead of `None`)
- `subtitle_margin_v` has hardcoded default `340` (instead of `None`)
- `highlight_words`, `highlight_color` missing entirely
- `sfx_start_sec`, `resolution`, `fps`, `crf`, `encoder`, `preview_seconds` missing
Practically: this endpoint cannot reproduce the same render as `/api/render/start`. It should be deprecated in favour of `/api/render/start`.

### BUG-2: `probe_video` doesn't return `needs_proxy` for audio-only streams
If `codec == "h264"` but `pix_fmt` is `"yuvj420p"` — actually handled correctly (included in `not needs_proxy`). But if the file is **10-bit** (`yuv420p10le`) it correctly sets `needs_proxy=true`. This is correct behaviour, not a bug per se. *(No actual bug here — documented for clarity.)*

### BUG-3: `clip_end` validator allows `clip_end > video_duration`
`RenderParams` validator only checks `clip_end > clip_start`. It does NOT check `clip_end <= video_duration`. The cap happens later in `resolve_clip()` via `min(clip_end, meta["duration"])`. This is safe but silently truncates; a user passing `clip_end=99999` gets no validation error at the Pydantic layer.

### BUG-4: `clip_end` Field default is `None` with `gt=0` — allows `clip_end=0` to pass as `None`
Actually Pydantic will reject `clip_end=0` since `gt=0` applies when not `None`. This is correct. *(No bug.)*

### BUG-5: `safe_child` path-traversal check has off-by-one
```python
if base.resolve() not in target.parents:
```
`target.parents` does **not** include `target` itself, so a file directly in `base` with the same name as `base` would fail. In practice this is fine since files always have extensions. Not a security issue.

### BUG-6: `ensure_default_sfx` calls `_run(["ffmpeg", ...])` at app startup — blocks if FFmpeg is slow
Called synchronously during `app = FastAPI(...)` startup (before first request). If FFmpeg is slow or absent, app startup blocks/logs silently. The function does `except RuntimeError: return` so it won't crash, but SFX presets may be missing silently.

### BUG-7: `youtube_engine` CACHE_DIR writes to `ROOT/.cache/yt-dlp`
`ROOT` is `Path(__file__).resolve().parent.parent` = `E:\SupaisuClip`. Cache goes to `E:\SupaisuClip\.cache\yt-dlp`. This is correct per GEMINI.md rules.

### BUG-8: `/api/render` legacy endpoint: `webcam_src_json` parsed from JSON but schema is `{}` default
If `webcam_enabled=false`, `webcam_src` is set to `None` (correct). But if `webcam_enabled=true` and `webcam_src_json="{}"`, then `Rect` validation fails (missing `x, y, w, h`) raising unhandled 422/500 instead of a clean 400. The `except (ValueError, json.JSONDecodeError)` block should catch it, but the Pydantic error is `ValidationError`, which is NOT caught there — it will bubble as a 500. **Actual bug.**

### BUG-9: `_amix_has_normalize` is `@lru_cache` but runs `ffmpeg` at import time (first call)
Actually it only runs at first audio mix render. Fine.

### BUG-10: `font_size=0` in `build_ass_text` check is falsy — style fontsize not overridden
In `build_ass_text`:
```python
if font_size:    # 0 is falsy!
    st["fontsize"] = int(font_size)
```
If `font_size=0` is passed (impossible via Pydantic since `ge=16`), it would silently use style default. Pydantic blocks 0, so safe. Not a real bug.

### BUG-11: `clip_end` with value `None` passed to `resolve_clip` — video duration used as cap. No issue.

### BUG-12: Legacy `/api/render` does NOT validate `webcam_src_json` as a valid `Rect` when `webcam_enabled=True`
If `webcam_src_json` is `{}`, Pydantic `RenderParams` construction fails with `ValidationError` (not `ValueError`), which is **not caught** by `except (ValueError, json.JSONDecodeError)`. The exception propagates as HTTP 500. **Confirmed bug** (same as BUG-8 — consolidated).

## (e) Does `/api/preview/ass` support `absolute_time`?

**YES. Confirmed.**

`PreviewAssRequest` extends `RenderParams` and adds:
```python
absolute_time: bool = False
```
In the endpoint handler:
```python
shift = cs if req.absolute_time else 0.0
return { "ass_text": ass_from_params(req, meta, time_shift=shift), ... }
```
When `absolute_time=True`, all ASS event timestamps are shifted forward by `clip_start` seconds, making them match the full video timeline. This is needed for JASSUB when the player is showing the original (uncut) video.

When `absolute_time=False` (default), timestamps start at 0 — correct for a clipped preview player.

## (f) What is `needs_proxy` in probe result?

Defined in `video_engine.probe_video()`:
```python
"needs_proxy": not (codec == "h264" and pix_fmt in ("yuv420p", "yuvj420p")),
```

**Meaning:** `True` if the browser **cannot natively play** this video (e.g., HEVC/H.265, ProRes, AV1, 10-bit H.264, VP9 in some browsers).  
**Only** plain 8-bit H.264 with `yuv420p` or `yuvj420p` pixel formats are considered browser-safe (`needs_proxy=False`).

Frontend should call `/api/video/proxy` after upload if `meta.needs_proxy == true`. The proxy endpoint creates a `_proxy.mp4` (libx264, 720p, `yuv420p`) for in-browser preview. The **render always uses the original file** regardless of proxy status.

## (g) JASSUB Integration Notes

JASSUB is a JavaScript library that renders `.ass` subtitle files in the browser using WebAssembly (libass compiled to WASM). Integration points:

1. **ASS source:** Call `POST /api/preview/ass` with the current `EditState` to get `ass_text`.
2. **Player mode:** 
   - If playing the **full (uncut) video** in browser: use `absolute_time: true` — timestamps will be offset by `clip_start`.
   - If playing a **trimmed** segment (browser clips via `currentTime` seek + limited duration): use `absolute_time: false`.
3. **PlayRes:** Backend always outputs `PlayResX: 1080, PlayResY: 1920`. JASSUB must be initialized with the same canvas dimensions (or let JASSUB scale).
4. **Font loading:** Custom fonts are served at `/files/fonts/<filename>`. Pass them to JASSUB's `availableFonts` or `fetchFonts` option so libass can resolve the `font_family` name used in the ASS `Style` line.
5. **Live preview:** On any EditState change, debounce (~300ms) then re-fetch `/api/preview/ass` and call `jassub.setTrack(ass_text)` to update subtitles without reloading the video.
6. **Hook layer:** The hook banner uses `Style: HookBanner` with `Alignment: 8` (top-center). It is a separate Dialogue event at the highest layer (Layer 2) so it renders above subtitles (Layer 1).
7. **Animation:** Subtitles use `\t(0,80,\fscx100\fscy100)` — a 80ms pop-in scale animation. JASSUB supports `\t` transforms; this should work correctly.
8. **Highlight color:** Applied inline per word via `\c&HBBGGRR&` override tags — no JASSUB-specific consideration needed.

## (h) Open Questions

1. **Frontend state persistence:** Is `EditState` persisted in localStorage or only in React state? If the page reloads, does the user lose their clip/settings?
2. **Multiple concurrent renders:** Backend uses `threading.Semaphore(1)` — only one render at a time. Queue depth is unbounded (`RENDER_JOBS` dict). Should there be a maximum queue depth?
3. **RENDER_JOBS memory leak:** `RENDER_JOBS` is an in-memory dict that grows indefinitely. No eviction policy. Long-running server will accumulate all job states forever.
4. **YouTube download job eviction:** Same issue — `JOBS` in `youtube_engine` never evicts.
5. **SFX presets not versioned:** `ensure_default_sfx` only checks if the file exists, not if it matches the current preset definition. If the preset code changes, old files remain.
6. **`fps` field:** Backend accepts `fps` as `int|None`. Frontend needs a UI control for this — is it exposed? Default `None` preserves source FPS.
7. **Preview render resolution:** When `preview_seconds` is set, `render_vertical_clip` forces `resolution=540` internally, overriding the `resolution` parameter. Frontend should not expose `resolution` for preview renders.
8. **JASSUB version compatibility:** Which version of JASSUB is planned? API for `setTrack` vs `setTrackByUrl` varies.
9. **`540` resolution not in `RenderParams`:** `Literal[1080, 720]` only. The 540 is used only internally by preview render. Confirm this is intentional.
10. **SFX file cleanup:** Uploaded SFX files and fonts are never deleted. Need a housekeeping strategy for disk space.
11. **Export file cleanup:** Exported MP4s accumulate in `workspace/exports/`. No TTL or cleanup mechanism.
12. **`webcam_src` coordinate system:** `Rect.x/y` are top-left in 0-1 ratios relative to source video. Is this clearly documented for the frontend developer?
